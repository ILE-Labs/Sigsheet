# Background: what the design rests on

The facts about CKB's multisig lock, today's wallets, CoBuild, CKB IDL and other ecosystems that the [design record](design-record.md) builds on. Each line links to its source: a permalink at the commit listed in [sources.md](sources.md), an RFC, a public post, or an experiment in this repository. Code facts are dated by their commits: ckb-system-scripts `72eb92f` (2025-05-13), ckb-cli v2.0.0 `80efc21` (2025-12-03), ckb-sdk v5.0.0 `3a418e7` (2025-10-31), Neuron v0.204.1 `d3a7467` (2026-04-10), CCC `@ckb-ccc/core` 1.23.1 `7095cca` (2026-11-17).

## 1. The multisig lock

The lock is `secp256k1_blake160_multisig_all` ([source](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c)).

- **Args:** 20 bytes (the blake160 of the multisig script), or 28 bytes (plus an 8-byte little-endian `since`); any other length fails with `ERROR_ARGUMENTS_LEN` ([L110-L118](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L110-L118)). Blake160 is the first 20 bytes of blake2b-256 with the personalisation "ckb-default-hash" ([L79-L81](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L79-L81)).
- **Witness lock:** `S | R | M | N | N × 20-byte key hashes | M × 65-byte signatures`, where S must be 0, N > 0, 0 < M ≤ N and R ≤ M ([L13-L27](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L13-L27), [L168-L180](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L168-L180)). The lock must be exactly `4 + 20N + 65M` bytes, else `ERROR_WITNESS_SIZE` ([L186-L188](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L186-L188)).
- **Binding:** the blake160 of the script part (not the signatures) must equal the args, else `ERROR_MULTSIG_SCRIPT_HASH` ([L191-L199](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L191-L199)).
- **The signing message** ([L205-L281](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L205-L281)) is blake2b over:
  1. the transaction hash;
  2. the first witness of the lock group, preceded by its length as a u64 little-endian, with the M × 65 signature bytes set to zero;
  3. each other witness of the lock group, each preceded by its length;
  4. every witness whose index is at or beyond the number of inputs, each preceded by its length ([L259-L278](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L259-L278)).

  The loop over group witnesses stops at the first group input that has no witness ([L235-L238](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L235-L238)). Witnesses are read into a 32 KB buffer ([L67](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L67)).
- **Matching:** each of the M signatures is recovered and must match a key that hasn't been used yet; order doesn't matter; then each of the first R keys must have been used; otherwise `ERROR_VERIFICATION` (-52) ([L286-L361](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L286-L361)). [X1](experiments/X1/results.md#devnet-transactions-all-committed) showed -52 for two valid members without the required one (case S4N).
- **Since:** `check_since` requires every input of the group to have the same since flags as the args' since, and a value at least as large ([common.h L88-L125](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/common.h#L88-L125)).
- **The single-key lock** (`secp256k1_blake160_sighash_all`) uses the same message rule with the whole 65-byte lock zeroed ([sighash_all.c L159](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_sighash_all.c#L159)), and requires 20-byte args ([L106](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_sighash_all.c#L106)).
- **The message does not cover the input cells** (their capacity, lock, type or data). It covers the transaction hash and the witnesses, and the transaction hash covers the inputs' out points, not the cells ([RFC 0022 L59-L61](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0022-transaction-structure/0022-transaction-structure.md#L59-L61)). The proposed CKB_TX_MESSAGE_ALL would sign the input cells ([rfcs#446](https://github.com/nervosnetwork/rfcs/pull/446)).
- **High-s signatures:** the secp256k1 the lock is built with (`deps/secp256k1` at `3ffde18`) rejects only r or s at or above the group order when parsing, and only zero values or invalid points when recovering ([main_impl.h L38-L119](https://github.com/nervosnetwork/secp256k1/blob/3ffde18a060aaf4df5b81e7d88355f1e99874650/src/modules/recovery/main_impl.h#L38-L119)). So a signature's malleated twin is valid too; [X4](experiments/X4/results.md#1-the-lock-accepts-a-malleated-signature-on-all-three-deployments-run-on-chain) committed one on each deployment. A zero signature slot fails recovery, so an incompletely signed transaction can't commit ([L314](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/secp256k1_blake160_multisig_all.c#L314)).

## 2. Transaction structure and hash

- The transaction hash is ckbhash (blake2b-256, "ckb-default-hash") of the Molecule-encoded RawTransaction: everything except the witnesses ([RFC 0022 L388-L392](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0022-transaction-structure/0022-transaction-structure.md#L388-L392)).
- Inputs are out points (a previous transaction hash and index) plus `since`; the input's capacity, lock, type and data live in the previous transaction's output ([RFC 0022 L93](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0022-transaction-structure/0022-transaction-structure.md#L93)). So a signer who has the previous transaction can check an input cell by hashing that transaction and matching the out point; [X1](experiments/X1/results.md#interoperability-findings) did this for Neuron's `context` and ckb-cli's `used_input_txs`. The raw transaction is enough: its witnesses aren't hashed ([X2a](experiments/X2a/results.md)).
- `since`: 0 disables it; the top bit selects relative or absolute; two flag bits select block number, epoch with fraction, or median timestamp ([RFC 0017 L45-L59](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0017-tx-valid-since/0017-tx-valid-since.md#L45-L59)).
- A multisig address is the full-format address (`0x00 | code_hash | hash_type | args`, bech32m); the short multisig format is deprecated ([RFC 0021](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0021-ckb-address-format/0021-ckb-address-format.md#L36)).
- The independent Molecule encoder in [`experiments/X1/scripts/ckbcore.py`](experiments/X1/scripts/ckbcore.py) reproduces the hash of every mainnet and devnet transaction used in the experiments.

Sources: CCC's tables ([mainnet](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/client/clientPublicMainnet.advanced.ts#L51), [testnet](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/client/clientPublicTestnet.advanced.ts#L58)); every code hash was confirmed from mainnet chain data in [X1](experiments/X1/README.md).

- **Code differences:** with comments removed, the multisig source is identical from v0.5.1 (2019-11-08) to just before the 2024 fix. The 2024 fix sizes `used_signatures` by N instead of M ([commit 9341664](https://github.com/nervosnetwork/ckb-system-scripts/commit/934166406fafb33e299f5688a904cadb99b7d518)). v2 calls `check_since` only when the args carry a since ([PR #99](https://github.com/nervosnetwork/ckb-system-scripts/pull/99)), so the genesis and 2024 versions always call `check_since(0)` and reject a group input whose since has any flag set ([XRT-3](experiments/XRT/results.md#xrt-3-a-lock-the-reader-doesnt-sign) part C). A core developer described the genesis multisig as containing "a bug that, under certain conditions, may fail to verify valid signatures" ([ckb#4788](https://github.com/nervosnetwork/ckb/issues/4788#issuecomment-2600748876)); [XRT-1](experiments/XRT/results.md#xrt-1-which-valid-signature-sets-each-deployed-binary-accepts) measured which sets it rejects.
- **All three use the same witness layout and the same message rule;** the diffs touch neither. The devnet's bundled genesis binary is byte-identical to mainnet's, and the experiments copied the 2024 and v2 binaries from mainnet ([X1](experiments/X1/README.md)).
- **Where the funds are** (2026-11-18, capacity under each deployment's lock by indexer search on the code hash): genesis 1,234,377,802.05 CKB; 2024 5,884,417.54 CKB; v2 961,257.00 CKB ([X1](experiments/X1/README.md), `data/mainnet/multisig-capacity-by-deployment.json`, a mainnet input; see [mainnet-inputs.md](experiments/mainnet-inputs.md)).
- **Who supports which:** CCC signs all three by default ([signerMultisigCkbReadonly.ts L366](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/signer/ckb/signerMultisigCkbReadonly.ts#L366)). ckb-cli accepts only the genesis (`type`) and v2 (`data1`) code hashes ([tx_helper.rs L258](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/utils/tx_helper.rs#L258)) and refused the 2024 lock in X1. Neuron defines only those two ([.env L117](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/.env#L117)) and throws "Unknown Multisig Code Hash" for the 2024 one ([X1](experiments/X1/results.md#interoperability-findings)).

## 4. ckb-cli 2.0.0 and ckb-sdk 5.0.0

- **The `tx` file** (`ReprTxHelper`): `transaction` (RPC JSON), `multisig_configs` keyed by the 20-byte script hash, `signatures` keyed by lock args, each a list ([tx.rs L775-L778](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/subcommands/tx.rs#L775-L778)). It carries no input cells; `add-input`, `sign-inputs`, `info` and `send` read live cells from a node ([tx.rs L313](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/subcommands/tx.rs#L313)).
- **Signing:** `sign_inputs` groups inputs by lock and signs a multisig group only if the key is in the config ([tx_helper.rs L210-L294](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/utils/tx_helper.rs#L210-L294)). `build_signature` follows the lock's message rule exactly, including witnesses beyond the inputs ([L507-L566](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/utils/tx_helper.rs#L507-L566)).
- **Finalizing:** `build_tx` requires exactly the threshold number of signatures per lock args ("Invalid multisig signature length for lock_arg: …", [L331-L339](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/utils/tx_helper.rs#L331-L339)). On the devnet, three signatures for a 2-of-3 were refused with that message, and exactly two were sent ([X1](experiments/X1/results.md#side-check-more-than-m-signatures-in-ckb-cli)).
- **The deploy info file** (`IntermediumInfo`) carries `used_input_txs` (the full input transactions) and signatures as lists ([intermedium_info.rs L22](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/subcommands/deploy/intermedium_info.rs#L22)); `sign-txs` prints one signature per lock args and writes it into the signer's own file only with `--add-signatures` ([deploy/mod.rs L679-L723](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/subcommands/deploy/mod.rs#L679-L723)). Its multisig config's `lock_code_hash` defaults to the genesis code hash "for compatibility" ([tx.rs L848-L859](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/subcommands/tx.rs#L848-L859)); in the real PR #34 file it names the genesis code hash although the lock is v2 ([X1](experiments/X1/results.md#interoperability-findings)).
- **Keys:** a private-key file, the keystore, hardware or plugin signers ([signer.rs](https://github.com/nervosnetwork/ckb-cli/blob/80efc21c30e9fc7847407a217034681b6e46c763/src/utils/signer.rs#L59)).
- **ckb-sdk 5.0.0:** `SecpMultisigScriptSigner` builds the zeroed lock at its final length, refuses an existing lock of any other length, and puts each signature in the first zero slot ([signer.rs L336-L374](https://github.com/nervosnetwork/ckb-sdk-rust/blob/3a418e7048c8864c15548e838072495edefbc24f/src/unlock/signer.rs#L336-L374)); `generate_message` follows the lock's rule, including witnesses beyond the inputs ([L475-L538](https://github.com/nervosnetwork/ckb-sdk-rust/blob/3a418e7048c8864c15548e838072495edefbc24f/src/unlock/signer.rs#L475-L538)). Its `MultisigConfig` is 125 lines ([L142-L266](https://github.com/nervosnetwork/ckb-sdk-rust/blob/3a418e7048c8864c15548e838072495edefbc24f/src/unlock/signer.rs#L142-L266)).

## 5. Neuron v0.204.1

- **The offline JSON** (`OfflineSignJSON`): `transaction` (Neuron's camelCase model), `status`, `type`, `context` (the input transactions), optional `description`, `asset_account`, `multisig_configs`, `signatures` ([offline-sign.ts L4-L43](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/models/offline-sign.ts#L4-L43)). Export fetches `context` by RPC when it's missing ([controllers/offline-sign.ts L46-L61](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/controllers/offline-sign.ts#L46-L61)).
- **Partial signatures** are appended after the multisig script in the witness lock, so the lock grows by 65 bytes each time; who signed is in `transaction.signatures`, keyed by the lock hash ([transaction-sender.ts L321-L326](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/services/transaction-sender.ts#L321-L326)).
- **The message:** `signSingleMultiSignScript` hashes the transaction hash, the zeroed first witness and the group's other witnesses only; it leaves out witnesses at or beyond the number of inputs, and `signMultisig` keeps one witness per input ([L443-L490](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/services/transaction-sender.ts#L443-L490)). Confirmed by running Neuron's code (case S9, [X1](experiments/X1/results.md)).
- **The ckb-cli import** (`parseMultisigTxJsonFromCkbCli`) fills inputs that have no lock with the genesis multisig lock and never copies ckb-cli's signatures ([multisig.ts L46-L54](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/utils/multisig.ts#L46-L54)). Run with Neuron's own code, the two signatures in ckb-cli's file were dropped ([X1](experiments/X1/results.md#interoperability-findings)).
- **Ledger:** `signMultisig` hands signing to the device, sending the raw transaction, the witnesses and `context` ([transaction-sender.ts L308](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/services/transaction-sender.ts#L308), [ledger.ts L83](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/services/hardware/ledger.ts#L83)).

## 6. CCC (@ckb-ccc/core 1.23.1)

- **No file format:** the multisig signers work on a `Transaction` object, and the signatures live in the witness ([signerMultisigCkbReadonly.ts L85](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/signer/ckb/signerMultisigCkbReadonly.ts#L85)). `SignerMultisigCkbReadonly` defaults to the v2, 2024 and genesis scripts ([L349-L366](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/signer/ckb/signerMultisigCkbReadonly.ts#L349-L366)).
- **Partial signatures:** the lock is kept at its final length with unused slots zero-filled ([L518](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/signer/ckb/signerMultisigCkbReadonly.ts#L518)).
- **The message:** `getSignHashInfo` hashes the group's witnesses and every witness beyond the inputs; it needs a client to fetch the input cells and find the lock groups ([transaction.ts L1480-L1516](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/ckb/transaction.ts#L1480-L1516)). [X1](experiments/X1/README.md) ran it fully offline, with the input cells put into the client's cache.
- **Merging:** `aggregateTransactions` recovers each signature's key, keeps members only, drops duplicates, and stops at the threshold ([L615-L745](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/signer/ckb/signerMultisigCkbReadonly.ts#L615-L745)). It depends on the order of its inputs ([X3a](experiments/X3a/results.md)).
- **Reading Neuron's file:** `Transaction.from` accepts Neuron's exported transaction and computes the right hash, but turns its witness object into `0x`, losing the partial signature ([X1](experiments/X1/results.md#interoperability-findings)).
- **History:** multisig signers came with PR #349, v2 support with #197, and the since fix (#593) with 1.23.1 ([CHANGELOG](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/CHANGELOG.md#L17)).

## 7. The signing message across tools

- On 12 cases (2 real, 10 devnet; 15 lock groups), an independent implementation, CCC, ckb-cli 2.0.0's `build_signature` and ckb-sdk 5.0.0's signer give byte-identical messages on every group. Neuron's `signSingleMultiSignScript` matches on 12 of 13 multisig groups and differs only when there is a witness beyond the inputs ([X1](experiments/X1/results.md)).
- ckb-cli, CCC and Neuron produce byte-identical signatures for the same key and message (deterministic nonces), and 9 devnet transactions committed with signatures from different tools in one transaction ([X1](experiments/X1/results.md#devnet-transactions-all-committed)).

## 8. CoBuild and OTX

- **The building packet:** `BuildingPacket` is a union holding `BuildingPacketV1`, a table of `message`, `payload` (the transaction), `resolved_inputs` (the input cells and data), `change_output`, `script_infos` and `lock_actions` ([basic.mol L48](https://github.com/cryptape/ckb-transaction-cobuild-poc/blob/e29514f9b1206b40f2bbc7b97e86c6f35373b0b0/schemas/basic.mol#L48)). Its stated purpose: "BuildingPacket is the standard format for data exchange among parties during Transaction Co-build process", with `lock_actions` for temporary signing data such as multisig ([t/7702/1](https://talk.nervos.org/t/7702/1)).
- **CoBuild's signing message differs from the legacy one:** it covers the `Message`, the transaction hash, the input cells and their data, and extra witnesses ([t/7702/5](https://talk.nervos.org/t/7702/5)). So a CoBuild signature can't satisfy the existing multisig lock, which computes the legacy message (section 1). A CoBuild transaction can carry legacy `WitnessArgs` witnesses for legacy locks next to CoBuild witnesses ([t/7702/11](https://talk.nervos.org/t/7702/11)).
- **Status:** the overview (2024-02-08) says design and implementation are in progress ([t/7702/1](https://talk.nervos.org/t/7702/1)); the CoBuild items in ckb-kanban#33 were marked "Deferred" on 2024-12-23 ([comment](https://github.com/nervosnetwork/ckb-kanban/issues/33#issuecomment-2559132055)); RFC number 55 was reserved for CKB_TX_MESSAGE_ALL on 2026-10-26 ([rfcs#446](https://github.com/nervosnetwork/rfcs/pull/446#issuecomment-6415673953)). CCC 2.0's prerelease adds a `@ckb-ccc/co-build` package that implements only the `SighashAll` layout and defines no `BuildingPacket` (its CHANGELOG, in [CCC's packages at `8cdbf52`](https://github.com/ckb-devrel/ccc/tree/8cdbf527921fe84ecc2cab5ad511d21ef5960e34/packages)); CCC's `BuildingPacket` codec sits in `@ckb-ccc/spore`, which nothing else in CCC uses. CCC's maintainer reintroduced CoBuild only to simplify the Coin package ([t/10597/1](https://talk.nervos.org/t/10597/1), in Chinese).
- **OTX:** the 2023 OTX RFC ([rfcs#406](https://github.com/nervosnetwork/rfcs/pull/406)) was closed unmerged; CoBuild OTX delimits open transactions in witnesses ([basic.mol L73-L80](https://github.com/cryptape/ckb-transaction-cobuild-poc/blob/e29514f9b1206b40f2bbc7b97e86c6f35373b0b0/schemas/basic.mol#L73-L80)).

## 9. Omnilock's multisig mode and future locks

- **Omnilock's multisig mode** is auth flag `0x06` (`IdentityCkbMultisig = 6`, [ckb_identity.h L70](https://github.com/nervosnetwork/omnilock/blob/280dd97ac0930ea1ed766a18d49478229347c832/c/ckb_identity.h#L70)). It reads the same `S | R | M | N | key hashes | signatures` bytes, with the same checks and length rule, from `OmniLockWitnessLock.signature` ([L781-L813](https://github.com/nervosnetwork/omnilock/blob/280dd97ac0930ea1ed766a18d49478229347c832/c/ckb_identity.h#L781-L813), [L958-L962](https://github.com/nervosnetwork/omnilock/blob/280dd97ac0930ea1ed766a18d49478229347c832/c/ckb_identity.h#L958-L962)). Its message clears the whole lock field, where the multisig lock clears only the signature part ([RFC 0042 L124](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0042-omnilock/0042-omnilock.md#L124)), so the two locks sign different messages for the same transaction. Its args are "`<identity, 21 bytes> <omni_lock args>`" ([omni_lock.c L138](https://github.com/nervosnetwork/omnilock/blob/280dd97ac0930ea1ed766a18d49478229347c832/c/omni_lock.c#L138)), so the config key sits at args bytes 1-20.
- **Arbitrary multisig** ([rfcs#448](https://github.com/nervosnetwork/rfcs/pull/448)): a new script in which participants may use different signature algorithms; RFC number 56 was reserved for it on 2026-10-26 ([comment](https://github.com/nervosnetwork/rfcs/pull/448#issuecomment-6415977046)).

## 10. CKB IDL

- **What it defines today:** an IDL document for a lock's `witness_args.lock` interface, the `linear-0.1.0` encoding, a commitment to the code cell (Binding Trailer 1), RFC 8785 canonicalization, and author and client flows ([SPEC.md](https://github.com/ckb-idl/ckb-idl-spec/blob/ebec1696b3df3336262c479650611bb344489f01/SPEC.md#L18)). Its client flow says not to trust an IDL "merely because it parses" ([idl-client-flow.md](https://github.com/ckb-idl/ckb-idl-spec/blob/ebec1696b3df3336262c479650611bb344489f01/idl-client-flow.md#L12)).
- **What it defers:** the ROADMAP lists "Signing and partial-signing metadata." beyond 0.1.0, in a non-normative list ([ROADMAP.md L13](https://github.com/ckb-idl/ckb-idl-spec/blob/ebec1696b3df3336262c479650611bb344489f01/ROADMAP.md#L13)); "Rich signing metadata." is listed as deferred work ([t/10596/5](https://talk.nervos.org/t/10596/5)). Its registry plans "legacy attestations" in milestone M2 and TypeScript compatibility in M4, testnet-first ([RELEASE_PLAN.md](https://github.com/ckb-idl/script-registry/blob/b37ef146f897d1b78a633bd16df0536a5a978ad6/docs/RELEASE_PLAN.md)).
- **"Signing metadata" in its code** is only a non-normative struct: `SigningInfo`, "Legacy signing metadata container", with fields `algorithm`, `message` and `hasher` ([types.rs L45-L56](https://github.com/ckb-idl/ckb-idl-client/blob/e7d8124921dc640018004a4a031fc6146535e334/src/types.rs#L45-L56)). It describes a script's signing rule, not a transaction's partial signatures.
- **Its own place:** "The idea is partly inspired by Bitcoin's Partially Signed Bitcoin Transaction (PSBT) workflow, which makes transaction data portable between independent tools. [...] CKB IDL is intended to provide that complementary interface layer, allowing tools to discover and verify script-specific requirements before constructing or signing a transaction." ([t/11031/1](https://talk.nervos.org/t/11031/1)). Its author's motivation includes "a group of people passing a partially signed transaction around" ([t/10596/1](https://talk.nervos.org/t/10596/1)).
- **The existing multisig witness** can't be described in general, and no IDL can be verified for the deployed locks ([XC4](experiments/XC4/results.md)).

## 11. Prior art on CKB

- **A 2024 proof of concept** (cryptape/ckb-multisig-cobuild-poc, last commit 2024-03-05) used the building packet "as an intermediate format" for a legacy multisig transaction, with a `MultisigAction` lock action holding the config and the signatures; it supports ckb-cli and Neuron import and export, merges lock actions and signatures, checks readiness (threshold and required signers), and knows only the genesis multisig ([README L7-L15](https://github.com/cryptape/ckb-multisig-cobuild-poc/blob/84bdc99ad5e62f8e7a90a30e4d8bcdc1a53b468a/README.md#L7-L15), [transaction.js](https://github.com/cryptape/ckb-multisig-cobuild-poc/blob/84bdc99ad5e62f8e7a90a30e4d8bcdc1a53b468a/src/lib/transaction.js#L48), [multisig-lock-action.js](https://github.com/cryptape/ckb-multisig-cobuild-poc/blob/84bdc99ad5e62f8e7a90a30e4d8bcdc1a53b468a/src/lib/multisig-lock-action.js#L38)).
- **Requests and reports:** `request-signature` for ckb-cli ([ckb-cli#603](https://github.com/nervosnetwork/ckb-cli/issues/603)); the ckb-cli and Neuron signature mismatch ([ckb-cli#584](https://github.com/nervosnetwork/ckb-cli/issues/584)), "Should be resolved by" neuron#3169 ([neuron#3048](https://github.com/nervosnetwork/neuron/issues/3048#issuecomment-2154110104)); a P2P network for multisig wallets, one sentence and no design ([t/10794/5](https://talk.nervos.org/t/10794/5)).
- **An offline-signing draft** (2021): a molecule `UnsignedTransaction` with the transaction, its input transactions, cell dep transactions and headers, so an offline signer "can validate the correctness of input cells, by running a transaction hash check" ([t/5794/1](https://talk.nervos.org/t/5794/1)). It stayed a draft.
- **CKB Open Transaction** (2022): "a format to describe a partial CKB transaction and the allowed modifications" ([ckb discussion #3607](https://github.com/nervosnetwork/ckb/discussions/3607)); its RFC ([rfcs#406](https://github.com/nervosnetwork/rfcs/pull/406)) was closed unmerged.
- **CKB Action Links** ([t/10315](https://talk.nervos.org/t/10315), an early draft): a URL returns an open transaction that one wallet completes, signs and submits; it doesn't cover multisig.

## 13. Other ecosystems

- **Bitcoin PSBT (BIP-174):** the file carries the unsigned transaction and per-input data, so a signer needs nothing else ([L416](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L416)); partial signatures are keyed by public key ([L172](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L172)); Combiners merge files for the same transaction and may "pick arbitrarily when conflicts occur" ([L499-L502](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L499-L502)); binary or Base64 ([L537](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L537)); signers may show addresses, values and the fee ([L421](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L421)). **Changed after release:** "Many wallets began requiring the full previous transaction … for segwit inputs when PSBT was already in use" ([L156](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L156)), because an "attacker could trick a user to sending Bitcoin to fees" ([L415](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L415)).
- **PSBT v2 (BIP-370)** was made because v0's fixed global transaction couldn't take new inputs or outputs ([L17](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0370.mediawiki#L17)). **Taproot (BIP-371)** added fields for any PSBT version with no version change, because older software ignores unknown fields ([L161](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0371.mediawiki#L161)). Signers pass unknown keys through; the version number exists "only as a safeguard" for incompatible changes ([BIP-174 L546-L550](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0174.mediawiki#L546-L550)).
- **Liquid PSET:** BIP-370 plus confidential-transaction fields and a Blinder role; duplicate proprietary fields block combining unless identical ([pset.mediawiki L27-L31](https://github.com/ElementsProject/elements/blob/3c40bb994720616841715448cb9957ada984c556/doc/pset.mediawiki#L27-L31), [L423](https://github.com/ElementsProject/elements/blob/3c40bb994720616841715448cb9957ada984c556/doc/pset.mediawiki#L423)).
- **Kaspa PSKT:** per-input UTXO entries, partial signatures keyed by public key, JSON in a `PSKT`-prefixed hex string, and a Combiner that errors on mismatched versions ([pskt.rs](https://github.com/kaspanet/rusty-kaspa/blob/338d13c13826531ccbf9b29df4c2bdaeef895900/wallet/pskt/src/pskt.rs#L162-L177), [global.rs](https://github.com/kaspanet/rusty-kaspa/blob/338d13c13826531ccbf9b29df4c2bdaeef895900/wallet/pskt/src/global.rs#L40-L51)).
- **Zcash PCZT:** roles from BIP-174 and BIP-370 plus a Verifier, a Redactor and a Prover; a binary format with a magic and a version; a low-level signer role for constrained devices; roles designed so a hostile Creator, Updater or Combiner can't induce unauthorized spends ([README](https://github.com/zcash/librustzcash/blob/33644a5da0017de271ab0f057aeefdbce6684461/pczt/README.md#L6), [lib.rs](https://github.com/zcash/librustzcash/blob/33644a5da0017de271ab0f057aeefdbce6684461/pczt/src/lib.rs#L59), [roles.rs](https://github.com/zcash/librustzcash/blob/33644a5da0017de271ab0f057aeefdbce6684461/pczt/src/roles.rs#L102)). Its Combiner fails when one key has two different values.
- **Cosmos SDK:** an unsigned transaction made with `--generate-only`, and `tx multisign` combines separate signature files ([tx_multisign.go](https://github.com/cosmos/cosmos-sdk/blob/bd8cd0e3744bbee3f846f00a2f194fb589ab8efa/x/auth/client/cli/tx_multisign.go)); users also pass one file along, each signer appending a signature ([cosmos-sdk#8141](https://github.com/cosmos/cosmos-sdk/issues/8141)). ADR-050 added `SIGN_MODE_TEXTUAL` because hardware wallets can't decode Protobuf ([ADR-050](https://github.com/cosmos/cosmos-sdk/blob/bd8cd0e3744bbee3f846f00a2f194fb589ab8efa/docs/architecture/adr-050-sign-mode-textual.md)).
- **Cardano:** one witness file per signer, assembled with the body; CIP-30's `signTx` with `partialSign` returns only the new witnesses; CIP-21 requires canonical CBOR for hardware wallets, which stream and hash the body in chunks ([CIP-30](https://github.com/cardano-foundation/CIPs/blob/a4068a577790e7b17d2d6f00f6e54990cfcb7955/CIP-0030/README.md), [CIP-21](https://github.com/cardano-foundation/CIPs/blob/a4068a577790e7b17d2d6f00f6e54990cfcb7955/CIP-0021/README.md)).
- **Solana:** signers sign the same serialized message bytes; a coordinator merges, and must check each signature belongs to a required signer; any change voids every signature ([partial signing](https://github.com/solana-foundation/solana-com/blob/14537348c72053ef5cf46945762d2799679dbd78/apps/docs/content/docs/en/core/transactions/partial-signing.mdx)).
- **Safe:** a transaction service collects signatures off chain through a REST API; any owner executes once the threshold is met ([overview](https://github.com/safe-global/safe-docs/blob/e0e4f1d5cc7b3a8382fc34ae7c9153374d9a0e4e/pages/core-api/transaction-service-overview.mdx), [signatures](https://github.com/safe-global/safe-docs/blob/e0e4f1d5cc7b3a8382fc34ae7c9153374d9a0e4e/pages/advanced/smart-account-signatures.md)).
- **Polkadot:** `pallet-multisig` gathers approvals on chain, with a deposit reserved until execution or cancellation ([README](https://github.com/paritytech/polkadot-sdk/blob/fb5166f49c6838ad45dfac4921109e9b65527fa9/substrate/frame/multisig/README.md)).

## 14. Security lessons

- **Signers who can't check input amounts can be robbed through the fee.** BIP-143's signing didn't let a hardware wallet check segwit input amounts, so an attacker could get two signatures that combine into a transaction sending the coins to fees; fixed by requiring the full previous transactions; CVE-2020-14199 ([Trezor's advisory](https://trezor.io/vulnerability/possible-large-transaction-fee-via-two-segwit-transactions)). The CKB multisig message doesn't cover input cells either (section 1).
- **What the device shows can differ from what it signs:** a compromised USB host could rewrite a staged PSBT after review and before signing ([Coldcard disclosures](https://coinkite.com/historical-disclosures)).
- **A coordinator can swap the other signers' keys:** a hardware wallet that didn't check it owned one of a multisig's registered keys let a compromised coordinator substitute attacker keys ([BitBox, 2020](https://blog.bitbox.swiss/en/remote-multisig-theft-attack-on-the-coldcard-hardware-wallet/)); a swapped key in a stored copy of the wallet setup locks the owners out ([BitBox](https://blog.bitbox.swiss/en/how-nearly-all-personal-hardware-wallet-multisig-setups-are-insecure/)).
- **Multisig signers have approved what a compromised interface showed them.** Bybit (2025-02-21): more than $1.4 billion from a 3-signer Safe, after malicious JavaScript in the wallet's front end replaced the intended transaction ([NCC Group](https://www.nccgroup.com/research-blog/in-depth-technical-analysis-of-the-bybit-hack/)). Radiant Capital (October 2024): malware showed legitimate data in the front end while malicious transactions went to the hardware wallets ([Halborn](https://www.halborn.com/blog/post/explained-the-radiant-capital-hack-october-2024)).
- **Threshold signatures:** FROST ([RFC 9591](https://www.rfc-editor.org/rfc/rfc9591.txt)) and MuSig2 ([BIP-327](https://github.com/bitcoin/bips/blob/a7f91321f25b5be8d93e901775621c21519e80b7/bip-0327.mediawiki#L47)) produce Schnorr signatures that verify as a single signer's under a group key; signers must keep nonces secret and never reuse them. Threshold ECDSA implementations have repeatedly let one malicious party extract the whole key ([TSSHOCK](https://www.verichains.io/tsshock/verichains-tsshock-wp-v1.0.pdf)). An existing CKB multisig address fixes its members, and the lock needs M recoverable ECDSA signatures from M distinct members (section 1), so a threshold scheme can't spend an existing address ([paths.md](paths.md), path G).

## 15. CKB limits, the indexer and the Nervos DAO

- **Block size:** "The default maximum allowed size in bytes for a block" is 597,000 bytes ([consensus.rs L72-L83](https://github.com/nervosnetwork/ckb/blob/2592ddf0502cd4adfe886db893cccc866db3c60f/spec/src/consensus.rs#L72-L83), ckb v0.210.0). The transaction pool's size limit is 512,000 bytes ([X7](experiments/X7/results.md#3-limits)).
- **The default `min_fee_rate`** is 1,000 shannons per KB ([ckb.toml L212](https://github.com/nervosnetwork/ckb/blob/2592ddf0502cd4adfe886db893cccc866db3c60f/resource/ckb.toml#L212)).
- **Cell capacity:** a cell needs at least 61 CKB, and "every 100,000,000 Shannons give 1-byte storage" ([rpc/README.md L5876-L5903](https://github.com/nervosnetwork/ckb/blob/2592ddf0502cd4adfe886db893cccc866db3c60f/rpc/README.md#L5876-L5903)).
- **The Nervos DAO:** in a withdrawal "the sum of all output cells' capacity might exceed the sum of all input cells' capacity", and the maximum withdrawable capacity comes from the `dao` fields of the deposit and withdrawing blocks' headers ([RFC 0023 L44](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0023-dao-deposit-withdraw/0023-dao-deposit-withdraw.md#L44), [L128-L134](https://github.com/nervosnetwork/rfcs/blob/0c945451c24194f4d34d81195c0159df0a67581a/rfcs/0023-dao-deposit-withdraw/0023-dao-deposit-withdraw.md#L128-L134)). The DAO script finds the withdrawing block's header from the chain, by the input: `load_dao_header_data(input_index, CKB_SOURCE_INPUT, &withdraw_data)` ([dao.c L197](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/dao.c#L197)); it requires "Withdraw header must be after deposit header." ([L206](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/dao.c#L206)) and "Cell must at least be locked for one full lock period(180 epochs)" ([L234](https://github.com/nervosnetwork/ckb-system-scripts/blob/72eb92fca090700dcb398cd8cad8fbd8bad40355/c/dao.c#L234)). Nothing in the transaction names the withdrawing block except its hash among the header deps. Multisig DAO withdrawals are a real use: Neuron's request to "Support managing Nervos DAO assets with multisig addresses" was closed as completed ([neuron-public-issues#425](https://github.com/Magickbase/neuron-public-issues/issues/425)).
- **Known token scripts** (CCC 1.23.1's mainnet table): xUDT `0x50bd8d66…1b95` (`data1`), sUDT `0x5e7a36a7…cfd5` (`type`), Omnilock `0x9b819793…6f26` (`type`) ([clientPublicMainnet.advanced.ts L125-L296](https://github.com/ckb-devrel/ccc/blob/7095ccad564b94ea2e59284cb4a364aa3499252e/packages/core/src/client/clientPublicMainnet.advanced.ts#L125-L296)).
- **Relay message limits** in NIP-11's examples: 16,384 (the template), 524,288 and 65,535 bytes ([NIP-11 L99](https://github.com/nostr-protocol/nips/blob/bec0fc89e75645e77a06d145598246efca844457/11.md#L99), [L207](https://github.com/nostr-protocol/nips/blob/bec0fc89e75645e77a06d145598246efca844457/11.md#L207), [L234](https://github.com/nostr-protocol/nips/blob/bec0fc89e75645e77a06d145598246efca844457/11.md#L234)).

## 16. Hardware wallets: the Ledger Nervos app

- The app (`app-nervos` `8c50034`, version 0.6.3) hashes each input's previous transaction itself and uses that hash as the input's out point, so the amounts and fee it shows come from data it checked ([apdu_sign.c L316-L333](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L316-L333), [L490](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L490)).
- It recognizes only the single-key lock and the genesis multisig code hash; any other lock is rejected unless "contract data" is allowed ([L336-L357](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L336-L357)).
- It reads only M and N from the multisig witness and zeroes the signatures before hashing, so it doesn't check that its key is a member ([L858-L870](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L858-L870)). Neuron checks membership on the host ([transaction-sender.ts L323-L334](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/services/hardware/transaction-sender.ts#L323-L334)).
- It refuses a multi-input transaction with a multisig input ([L669](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L669)) and more than five outputs ([L576](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L576)); an output to a multisig is always shown as a destination ([L559](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L559)).
- Message-hash signing needs the "sign hash" setting ([L1297](https://github.com/LedgerHQ/app-nervos/blob/8c50034c8109f90d87c2b3c413361ef83f5b2e03/src/apdu_sign.c#L1297)); with it on, the app signs a 32-byte digest after showing it as hex, so a transaction's lock message can be signed blind ([XQ14](experiments/XQ14/results.md)).
- The host library Neuron pins (`@magickbase/hw-app-ckb` 0.2.0-alpha.0) pairs input i with context transaction i ([Ckb.js L243](https://github.com/magickbase/hw-app-ckb/blob/78fd71b48b4f33881e4f3c3170eb1ef780c69713/src/Ckb.js#L243)); Neuron's `hardware.ts` `signTx` handles only a one-input, one-key multisig ([hardware.ts L46-L51](https://github.com/nervosnetwork/neuron/blob/d3a7467d218e4b6f777326682a83fec802669c00/packages/neuron-wallet/src/services/hardware/hardware.ts#L46-L51)).
