# Contributing to Sigsheet

Thanks for your interest. Sigsheet is at an early stage, so the best contributions right now are questions and reports about real multisig workflows.

## Issues

- **Open an issue before a large change,** so the approach can be agreed first.
- **For a bug,** include the tool and version (ckb-cli, Neuron or CCC), the network, and a file or transaction that reproduces it, with any private data removed.
- **For the format,** describe the case it doesn't cover: the lock, the deployment and the transaction shape.

## Pull requests

- Keep each pull request to one change, split into small commits that each build.
- Write plain commit messages that say what changed.
- Add or update tests with every change. Changes to the format also need test vectors.
- Run the formatter, the linter and the full test suite before opening the pull request.

## Security

Don't report security issues in public issues. Email contact@ilelabs.org instead, with the steps to reproduce.
